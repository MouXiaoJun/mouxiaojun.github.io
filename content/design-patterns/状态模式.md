# 状态模式 State

> **核心思想：**对象在不同状态下行为不同时，把每种状态的规则封装起来，让状态转换本身成为显式模型。

状态模式适合订单、工单、连接、任务等生命周期复杂的对象。

## 先别急着用接口：简单状态机用 switch 更好

```go
type OrderStatus string

const (
    Pending OrderStatus = "pending"
    Paid    OrderStatus = "paid"
    Canceled OrderStatus = "canceled"
)

func (o *Order) Pay() error {
    switch o.Status {
    case Pending:
        o.Status = Paid
        return nil
    case Paid:
        return nil // 幂等
    case Canceled:
        return errors.New("canceled order cannot be paid")
    default:
        return errors.New("unknown order status")
    }
}
```

只有 3 个状态时，这可能就是最清楚的实现。

## 什么时候升级为 State 对象

当每个状态拥有大量行为：

```text
Pay
Cancel
Ship
Refund
Expire
```

每个方法都有巨大 switch，就开始适合 State。

```go
type State interface {
    Name() OrderStatus
    Pay(*Order) error
    Cancel(*Order) error
    Ship(*Order) error
}

type Order struct {
    ID    string
    state State
}

func (o *Order) transition(next State) {
    o.state = next
}

func (o *Order) Pay() error    { return o.state.Pay(o) }
func (o *Order) Cancel() error { return o.state.Cancel(o) }
func (o *Order) Ship() error   { return o.state.Ship(o) }
```

Pending 状态：

```go
type PendingState struct{}

func (PendingState) Name() OrderStatus { return Pending }

func (PendingState) Pay(o *Order) error {
    o.transition(PaidState{})
    return nil
}

func (PendingState) Cancel(o *Order) error {
    o.transition(CanceledState{})
    return nil
}

func (PendingState) Ship(*Order) error {
    return errors.New("pending order cannot be shipped")
}
```

Paid 状态：

```go
type PaidState struct{}

func (PaidState) Name() OrderStatus { return Paid }
func (PaidState) Pay(*Order) error  { return nil }
func (PaidState) Cancel(*Order) error {
    return errors.New("paid order must be refunded instead of canceled")
}
func (PaidState) Ship(o *Order) error {
    o.transition(ShippedState{})
    return nil
}
```

## 数据库并发不能靠内存 State 解决

两个实例同时读到 `pending`：

```text
A: Pay
B: Cancel
```

内存对象都认为自己的 transition 合法。落库时仍然需要 optimistic lock / CAS：

```sql
UPDATE orders
SET status = 'paid', version = version + 1
WHERE id = ? AND status = 'pending' AND version = ?;
```

受影响行数为 0，说明状态已经被别人改变。

**State 模式解决规则组织，不解决分布式并发。**

## 状态迁移测试

用表驱动描述允许/禁止关系比只测 happy path 更重要：

```text
pending -> pay    = paid
pending -> cancel = canceled
paid    -> ship   = shipped
canceled-> pay    = error
```

## State vs Strategy

结构都可能是对象持有接口并委托：

- Strategy：调用方选择算法；
- State：对象的内部状态决定行为，并且行为会触发状态迁移。

# 备忘录模式 Memento

> **核心思想：**在不暴露对象内部实现细节的情况下，保存某个时刻的状态，并允许以后恢复。

编辑器 Undo、配置回滚、游戏存档、工作流 checkpoint 都是典型 Memento。

## 场景：动态配置编辑与回滚

```go
type Config struct {
    Version int64
    Flags   map[string]bool
    Limits  map[string]int
}
```

如果直接保存指针：

```go
history = append(history, config)
```

后续修改 map 会把“历史版本”也一起改掉。

## Snapshot 必须拥有独立状态

```go
type Snapshot struct {
    version int64
    flags   map[string]bool
    limits  map[string]int
}

func (c *Config) Snapshot() Snapshot {
    return Snapshot{
        version: c.Version,
        flags:   maps.Clone(c.Flags),
        limits:  maps.Clone(c.Limits),
    }
}

func (c *Config) Restore(s Snapshot) {
    c.Version = s.version
    c.Flags = maps.Clone(s.flags)
    c.Limits = maps.Clone(s.limits)
}
```

`Snapshot` 字段不导出，外部只能保存和归还，不能随便篡改对象内部状态。

## Caretaker 管历史

```go
type History struct {
    snapshots []Snapshot
}

func (h *History) Save(c *Config) {
    h.snapshots = append(h.snapshots, c.Snapshot())
}

func (h *History) Undo(c *Config) bool {
    if len(h.snapshots) == 0 {
        return false
    }

    last := len(h.snapshots) - 1
    snapshot := h.snapshots[last]
    h.snapshots = h.snapshots[:last]
    c.Restore(snapshot)
    return true
}
```

使用：

```go
history.Save(cfg)
cfg.Flags["new-checkout"] = true

history.Undo(cfg)
```

## 大对象不要无限全量 Snapshot

如果 Config 有几百 MB，每次修改都深拷贝会非常贵。常见优化：

- 限制历史长度；
- 增量 diff；
- copy-on-write；
- event sourcing；
- 定期 checkpoint + 增量日志。

Memento 描述的是“恢复状态”的边界，不规定一定全量内存复制。

## 并发状态

如果对象会被多个 goroutine 修改，Snapshot/Restore 必须和修改操作共享一致的锁，否则可能保存到一个撕裂状态。

## 测试

```go
func TestUndoRestoresIndependentMaps(t *testing.T) {
    cfg := &Config{Flags: map[string]bool{"a": false}}
    var history History

    history.Save(cfg)
    cfg.Flags["a"] = true
    history.Undo(cfg)

    if cfg.Flags["a"] {
        t.Fatal("expected flag to be restored")
    }
}
```

## 和 Prototype 的区别

两者都可能涉及 Clone：

- Prototype：复制是为了**创建新对象**；
- Memento：复制是为了**以后恢复旧状态**。

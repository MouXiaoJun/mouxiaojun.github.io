# 代理模式 Proxy

> **核心思想：**调用方仍面向同一个接口，但中间增加一个代理来控制对真实对象的访问。

代理可以做远程调用、缓存、权限检查、延迟加载、熔断等。和 Decorator 相似的地方是“都包一层”，不同的是 Proxy 更关注**访问控制与访问策略**。

## 场景：远程用户服务前增加缓存代理

业务接口：

```go
type UserService interface {
    Get(ctx context.Context, id int64) (User, error)
}
```

真实远程对象：

```go
type RemoteUserService struct {
    baseURL string
    client  *http.Client
}

func (s *RemoteUserService) Get(ctx context.Context, id int64) (User, error) {
    req, err := http.NewRequestWithContext(
        ctx,
        http.MethodGet,
        fmt.Sprintf("%s/users/%d", s.baseURL, id),
        nil,
    )
    if err != nil {
        return User{}, err
    }

    resp, err := s.client.Do(req)
    if err != nil {
        return User{}, err
    }
    defer resp.Body.Close()

    if resp.StatusCode != http.StatusOK {
        return User{}, fmt.Errorf("user service returned %s", resp.Status)
    }

    var user User
    return user, json.NewDecoder(resp.Body).Decode(&user)
}
```

代理：

```go
type CachedUserService struct {
    next  UserService
    cache Cache[int64, User]
    ttl   time.Duration
}

func (s *CachedUserService) Get(ctx context.Context, id int64) (User, error) {
    if user, ok := s.cache.Get(id); ok {
        return user, nil
    }

    user, err := s.next.Get(ctx, id)
    if err != nil {
        return User{}, err
    }

    s.cache.Set(id, user, s.ttl)
    return user, nil
}
```

调用方仍然只知道：

```go
var users UserService = &CachedUserService{
    next: remote,
    cache: cache,
    ttl: 30 * time.Second,
}
```

## Proxy 可以隐藏远程边界

RPC stub 本质上就是 Remote Proxy：

```go
user, err := users.Get(ctx, 42)
```

调用看起来像本地方法，但内部可能跨网络。

这也意味着接口设计必须提醒调用方真实成本：不要因为“长得像本地方法”就在循环里调用 10,000 次。

## 权限代理

```go
type AuthorizedUserService struct {
    next UserService
}

func (s *AuthorizedUserService) Get(ctx context.Context, id int64) (User, error) {
    actor, ok := ActorFromContext(ctx)
    if !ok || !actor.CanReadUser(id) {
        return User{}, ErrForbidden
    }
    return s.next.Get(ctx, id)
}
```

多个代理也可以组合：

```text
Authorized -> Cached -> Remote
```

但组合一多，它就和 Decorator 链一样需要明确顺序。

## 缓存代理的真实坑

一个生产级缓存代理还要考虑：

- 缓存穿透；
- stale data；
- singleflight；
- negative cache；
- invalidation；
- metrics；
- context 取消时是否继续回填缓存。

模式只描述结构，不替你解决分布式缓存一致性。

## 测试缓存是否阻止重复访问

```go
type CountingUserService struct {
    Calls int
}

func (s *CountingUserService) Get(_ context.Context, id int64) (User, error) {
    s.Calls++
    return User{ID: id}, nil
}

func TestCacheProxy(t *testing.T) {
    real := &CountingUserService{}
    proxy := NewCachedUserService(real, NewMemoryCache(), time.Minute)

    _, _ = proxy.Get(context.Background(), 1)
    _, _ = proxy.Get(context.Background(), 1)

    if real.Calls != 1 {
        t.Fatalf("real service called %d times", real.Calls)
    }
}
```

## Proxy vs Decorator

- Proxy：决定**你能不能、何时、以什么成本访问真实对象**；
- Decorator：给对象**追加能力**。

实际代码可能长得一样，判断模式时看设计意图，而不是看 UML 名字。

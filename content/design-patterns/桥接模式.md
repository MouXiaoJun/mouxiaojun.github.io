# 桥接模式 Bridge

> **核心思想：**当一个功能有两个独立变化维度时，不要用继承/组合枚举出所有排列，而是把两个维度拆开，通过组合连接。

## 典型爆炸：消息类型 × 发送渠道

系统有：

```text
告警 / 营销 / 系统通知
```

发送渠道：

```text
Email / SMS / Webhook / Feishu
```

如果每种组合一个类型，会出现：

```text
AlertEmail
AlertSMS
MarketingEmail
MarketingSMS
SystemEmail
...
```

新增一个渠道，所有消息类型都要新增类。

## 把“消息语义”和“发送实现”拆开

```go
type Sender interface {
    Send(ctx context.Context, recipient, title, body string) error
}

type Notification struct {
    sender Sender
}

func NewNotification(sender Sender) Notification {
    return Notification{sender: sender}
}
```

渠道实现：

```go
type EmailSender struct {
    client *SMTPClient
}

func (s *EmailSender) Send(ctx context.Context, to, title, body string) error {
    return s.client.Send(ctx, to, title, body)
}

type FeishuSender struct {
    client *FeishuClient
}

func (s *FeishuSender) Send(ctx context.Context, webhook, title, body string) error {
    return s.client.Post(ctx, webhook, title+"\n"+body)
}
```

上层抽象可以独立演化：

```go
type Alert struct {
    Notification
    Service string
}

func (a Alert) HighCPU(ctx context.Context, target string, usage float64) error {
    title := fmt.Sprintf("[%s] high CPU", a.Service)
    body := fmt.Sprintf("cpu usage reached %.1f%%", usage)
    return a.sender.Send(ctx, target, title, body)
}
```

组合：

```go
alertByEmail := Alert{
    Notification: NewNotification(emailSender),
    Service:      "payment",
}

alertByFeishu := Alert{
    Notification: NewNotification(feishuSender),
    Service:      "payment",
}
```

`Alert` 的业务表达和 `Sender` 的传输实现可以各自增加，不会形成笛卡尔积类型爆炸。

## Go 中不需要模拟继承

教科书常把 Bridge 写成 `Abstraction / RefinedAbstraction / Implementor`。Go 里直接理解成：

```text
业务抽象 ----持有接口----> 基础设施实现
```

接口通常很小，组合通常比继承层级更自然。

## 测试业务抽象

```go
type RecordingSender struct {
    Title string
    Body  string
}

func (s *RecordingSender) Send(_ context.Context, _, title, body string) error {
    s.Title = title
    s.Body = body
    return nil
}

func TestAlertBuildsMessage(t *testing.T) {
    sender := &RecordingSender{}
    alert := Alert{Notification: NewNotification(sender), Service: "order"}

    if err := alert.HighCPU(context.Background(), "ops", 92.3); err != nil {
        t.Fatal(err)
    }
    if !strings.Contains(sender.Title, "order") {
        t.Fatalf("unexpected title: %s", sender.Title)
    }
}
```

## 什么时候值得用

- 两个维度都会独立增长；
- 组合数量明显开始膨胀；
- 希望业务能力和平台实现独立测试、独立替换。

如果只是一个维度变化，普通策略/接口注入通常已经足够。

## 和策略模式的区别

Bridge 强调**两个结构维度长期独立演化**；Strategy 强调**同一个行为在运行时选择不同算法**。代码形态可能类似，但设计意图不同。

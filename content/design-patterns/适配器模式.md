# 适配器模式 Adapter

> **核心思想：**在不修改既有代码的前提下，把一个“不符合当前接口”的对象转换成系统需要的接口。

后端项目里最典型的 Adapter 不是“插头转换器”，而是**第三方 SDK 统一接入**：微信支付、支付宝、不同短信厂商、不同对象存储 SDK 的方法名、参数、错误码都不一样，但业务层不应该知道这些差异。

## 问题：第三方类型开始污染业务层

假设两个支付 SDK：

```go
type WeChatClient struct{}
func (c *WeChatClient) UnifiedOrder(ctx context.Context, req WXOrderRequest) (WXOrderResponse, error)

type AliPayClient struct{}
func (c *AliPayClient) TradePay(ctx context.Context, req AliTradeRequest) (AliTradeResponse, error)
```

如果订单 Service 直接判断 provider：

```go
if provider == "wechat" {
    // 组 WXOrderRequest、解析 result_code
} else if provider == "alipay" {
    // 组 AliTradeRequest、解析 sub_code
}
```

第三方协议已经进入领域逻辑。

## 先定义自己的接口

接口应该由**使用方**定义，而不是照抄某个 SDK：

```go
package payment

import (
    "context"
    "time"
)

type ChargeRequest struct {
    OrderID string
    Amount  int64 // 分
    Subject string
}

type ChargeResult struct {
    TransactionID string
    PaidAt        time.Time
}

type Gateway interface {
    Charge(ctx context.Context, req ChargeRequest) (ChargeResult, error)
}
```

## 微信支付 Adapter

```go
type WeChatAdapter struct {
    client *WeChatClient
}

func NewWeChatAdapter(client *WeChatClient) *WeChatAdapter {
    return &WeChatAdapter{client: client}
}

func (a *WeChatAdapter) Charge(ctx context.Context, req payment.ChargeRequest) (payment.ChargeResult, error) {
    resp, err := a.client.UnifiedOrder(ctx, WXOrderRequest{
        OutTradeNo: req.OrderID,
        TotalFee:   req.Amount,
        Body:       req.Subject,
    })
    if err != nil {
        return payment.ChargeResult{}, fmt.Errorf("wechat unified order: %w", err)
    }
    if resp.ResultCode != "SUCCESS" {
        return payment.ChargeResult{}, fmt.Errorf("wechat rejected payment: %s", resp.ErrCode)
    }

    return payment.ChargeResult{
        TransactionID: resp.TransactionID,
        PaidAt:        resp.PaidAt,
    }, nil
}
```

支付宝 Adapter：

```go
type AliPayAdapter struct {
    client *AliPayClient
}

func (a *AliPayAdapter) Charge(ctx context.Context, req payment.ChargeRequest) (payment.ChargeResult, error) {
    resp, err := a.client.TradePay(ctx, AliTradeRequest{
        OutTradeNo: req.OrderID,
        AmountYuan: float64(req.Amount) / 100,
        Subject:    req.Subject,
    })
    if err != nil {
        return payment.ChargeResult{}, fmt.Errorf("alipay trade pay: %w", err)
    }

    return payment.ChargeResult{
        TransactionID: resp.TradeNo,
        PaidAt:        resp.GMTBefore,
    }, nil
}
```

业务层只依赖：

```go
type CheckoutService struct {
    gateway payment.Gateway
}
```

## Adapter 还应该做错误归一化

第三方可能返回：

```text
USERPAYING
SYSTEMERROR
ACQ.SYSTEM_ERROR
HTTP 429
```

系统内部最好统一成：

```go
var (
    ErrPaymentPending = errors.New("payment pending")
    ErrPaymentDeclined = errors.New("payment declined")
    ErrProviderBusy = errors.New("payment provider busy")
)
```

Adapter 不只是改字段名，更重要的是建立**反腐层（Anti-Corruption Layer）**，阻止外部语义穿透内部模型。

## 测试

```go
func TestWeChatAdapterMapsResponse(t *testing.T) {
    fake := &FakeWeChatClient{
        Response: WXOrderResponse{
            ResultCode:    "SUCCESS",
            TransactionID: "wx-100",
        },
    }

    adapter := NewWeChatAdapter(fake)
    got, err := adapter.Charge(context.Background(), payment.ChargeRequest{
        OrderID: "order-1",
        Amount:  9900,
    })
    if err != nil {
        t.Fatal(err)
    }
    if got.TransactionID != "wx-100" {
        t.Fatalf("unexpected transaction id %s", got.TransactionID)
    }
}
```

## 适合 / 不适合

适合：旧接口迁移、第三方 SDK、多厂商统一、基础设施替换。

不适合：两个接口本来就属于不同业务语义。不要为了“统一”把完全不同的行为硬塞到一个接口里。

## 和 Facade 的区别

- **Adapter**：解决接口不兼容，`A -> 你需要的 B`。
- **Facade**：把多个复杂子系统组合成一个更简单入口。

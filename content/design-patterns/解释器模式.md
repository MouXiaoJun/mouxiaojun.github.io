# 解释器模式 Interpreter

> **核心思想：**把一门小语言的语法表示成对象结构（AST），再让这些对象解释一个上下文。

解释器模式并不意味着你要造一门完整编程语言。权限表达式、过滤 DSL、活动规则、特性开关条件都可能只需要一个很小的表达式系统。

## 场景：规则条件

希望表达：

```text
country == "CN" AND level >= 3
```

先定义上下文：

```go
type Context map[string]any

type Expr interface {
    Eval(ctx Context) (bool, error)
}
```

叶子表达式：

```go
type Equals struct {
    Field string
    Value string
}

func (e Equals) Eval(ctx Context) (bool, error) {
    raw, ok := ctx[e.Field]
    if !ok {
        return false, fmt.Errorf("field %q not found", e.Field)
    }
    value, ok := raw.(string)
    if !ok {
        return false, fmt.Errorf("field %q is not string", e.Field)
    }
    return value == e.Value, nil
}

type GTE struct {
    Field string
    Value int64
}

func (e GTE) Eval(ctx Context) (bool, error) {
    value, ok := ctx[e.Field].(int64)
    if !ok {
        return false, fmt.Errorf("field %q is not int64", e.Field)
    }
    return value >= e.Value, nil
}
```

组合表达式：

```go
type And struct {
    Left  Expr
    Right Expr
}

func (e And) Eval(ctx Context) (bool, error) {
    left, err := e.Left.Eval(ctx)
    if err != nil || !left {
        return left, err
    }
    return e.Right.Eval(ctx)
}

type Not struct { Inner Expr }

func (e Not) Eval(ctx Context) (bool, error) {
    ok, err := e.Inner.Eval(ctx)
    return !ok, err
}
```

构造 AST：

```go
rule := And{
    Left: Equals{Field: "country", Value: "CN"},
    Right: GTE{Field: "level", Value: 3},
}

matched, err := rule.Eval(Context{
    "country": "CN",
    "level":   int64(5),
})
```

## Parser 和 Interpreter 是两回事

上面只是解释 AST。如果用户输入字符串：

```text
country == "CN" && level >= 3
```

你还需要 tokenizer/parser 把文本转换成 AST。

不要用一串脆弱的 `strings.Split` 假装 parser。DSL 一旦支持括号、转义、优先级，就应该：

- 使用成熟 parser；
- 或定义 JSON/YAML 结构化规则；
- 或明确限制语法。

例如很多业务场景用 JSON AST 更可靠：

```json
{
  "and": [
    {"eq": ["country", "CN"]},
    {"gte": ["level", 3]}
  ]
}
```

## 安全边界

如果 DSL 来自租户配置，要限制：

- AST 深度；
- 节点数量；
- 正则复杂度；
- 执行时间；
- 可访问字段白名单。

否则“配置规则”也可能变成 DoS 输入。

## 测试 AST 而不是只测 Parser

```go
func TestAndExpression(t *testing.T) {
    expr := And{
        Left: Equals{Field: "country", Value: "CN"},
        Right: GTE{Field: "level", Value: 3},
    }

    ok, err := expr.Eval(Context{"country": "CN", "level": int64(2)})
    if err != nil { t.Fatal(err) }
    if ok { t.Fatal("expected expression not to match") }
}
```

## 什么时候适合

规则结构相对稳定、表达式会被反复执行、用户需要组合条件时适合。

如果需求已经接近完整脚本语言，优先考虑 CEL、Starlark、Lua 等成熟方案，不要继续无限扩展自研 Interpreter。

# 观察者模式 Observer

> **核心思想：**一个对象状态变化时，自动通知一组订阅者；发布者只依赖订阅协议，不知道具体有哪些观察者。

事件总线、配置变更通知、WebSocket 广播、领域事件都能看到 Observer。

## 一个并发安全的进程内 Observer

```go
type Event struct {
    Topic string
    Data  any
}

type Observer func(context.Context, Event) error

type Bus struct {
    mu          sync.RWMutex
    subscribers map[string]map[uint64]Observer
    nextID      atomic.Uint64
}

func NewBus() *Bus {
    return &Bus{subscribers: make(map[string]map[uint64]Observer)}
}
```

订阅并返回 unsubscribe：

```go
func (b *Bus) Subscribe(topic string, observer Observer) func() {
    id := b.nextID.Add(1)

    b.mu.Lock()
    if b.subscribers[topic] == nil {
        b.subscribers[topic] = make(map[uint64]Observer)
    }
    b.subscribers[topic][id] = observer
    b.mu.Unlock()

    return func() {
        b.mu.Lock()
        delete(b.subscribers[topic], id)
        b.mu.Unlock()
    }
}
```

发布时**不要拿着锁执行用户回调**：

```go
func (b *Bus) Publish(ctx context.Context, event Event) error {
    b.mu.RLock()
    observers := make([]Observer, 0, len(b.subscribers[event.Topic]))
    for _, observer := range b.subscribers[event.Topic] {
        observers = append(observers, observer)
    }
    b.mu.RUnlock()

    for _, observer := range observers {
        if err := observer(ctx, event); err != nil {
            return err
        }
    }
    return nil
}
```

如果拿着 `RLock` 调 callback，而 callback 又 Subscribe/Unsubscribe，就可能产生难处理的锁依赖。

## 同步还是异步？

同步 Observer：

```text
Publish 返回时，所有 observer 已执行
```

优点是语义简单；缺点是慢 observer 会拖慢发布者。

异步 Observer：

```go
go observer(ctx, event)
```

看似简单，却马上需要回答：

- goroutine 数量是否有上限？
- panic 怎么处理？
- 进程退出等不等它？
- 错误去哪？
- event 是否可能丢失？

跨进程可靠事件不要用“随手 go 一下”，应该考虑消息队列/Outbox。

## Observer 的事件应该稳定

```go
type UserCreated struct {
    UserID string
}
```

比：

```go
type UserCreated struct {
    User *User // 暴露整个可变领域对象
}
```

更容易演进，也减少观察者互相通过共享指针产生隐式耦合。

## 测试取消订阅

```go
func TestUnsubscribe(t *testing.T) {
    bus := NewBus()
    calls := 0

    unsubscribe := bus.Subscribe("user.created", func(context.Context, Event) error {
        calls++
        return nil
    })

    _ = bus.Publish(context.Background(), Event{Topic: "user.created"})
    unsubscribe()
    _ = bus.Publish(context.Background(), Event{Topic: "user.created"})

    if calls != 1 {
        t.Fatalf("calls = %d", calls)
    }
}
```

## 适合场景

进程内低耦合通知、UI/配置监听、无需持久化的事件。

如果你需要“绝不丢消息、失败重试、消费者 offset”，那已经是消息系统问题，不只是 Observer 模式。

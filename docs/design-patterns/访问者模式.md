# 访问者模式 Visitor

> **核心思想：**当对象结构相对稳定、但针对这些对象的操作不断增加时，把操作从对象本身移到 Visitor。

Visitor 在 Go 里最常见的真实例子就是 AST：Go 自己的 `go/ast.Inspect` 也是在做结构遍历与外部操作分离。

## 场景：配置表达式 AST

节点类型：

```go
type Node interface {
    Accept(Visitor) error
}

type StringNode struct {
    Value string
}

type NumberNode struct {
    Value float64
}

type ObjectNode struct {
    Fields map[string]Node
}
```

Visitor：

```go
type Visitor interface {
    VisitString(*StringNode) error
    VisitNumber(*NumberNode) error
    VisitObject(*ObjectNode) error
}

func (n *StringNode) Accept(v Visitor) error { return v.VisitString(n) }
func (n *NumberNode) Accept(v Visitor) error { return v.VisitNumber(n) }

func (n *ObjectNode) Accept(v Visitor) error {
    if err := v.VisitObject(n); err != nil {
        return err
    }
    for _, child := range n.Fields {
        if err := child.Accept(v); err != nil {
            return err
        }
    }
    return nil
}
```

增加“统计敏感字段”操作，不需要修改节点类型：

```go
type SecretScanner struct {
    Count int
}

func (v *SecretScanner) VisitString(n *StringNode) error {
    if strings.Contains(strings.ToLower(n.Value), "secret") {
        v.Count++
    }
    return nil
}

func (v *SecretScanner) VisitNumber(*NumberNode) error { return nil }
func (v *SecretScanner) VisitObject(*ObjectNode) error { return nil }
```

以后还可以增加：

```text
ValidatorVisitor
JSONEncoderVisitor
MetricsVisitor
ReferenceCollector
```

而不把这些行为都塞进 AST Node。

## Go 里 type switch 往往更简单

如果节点不多，可以直接：

```go
func Validate(node Node) error {
    switch n := node.(type) {
    case *StringNode:
        // ...
    case *NumberNode:
        // ...
    case *ObjectNode:
        // ...
    }
    return nil
}
```

这通常比完整 Visitor 更 Go。

## Visitor 的真正取舍

Visitor 优化的是：**增加新操作很容易，增加新节点类型很痛苦。**

因为增加：

```go
type BoolNode struct{}
```

就必须修改 Visitor 接口，并让所有 Visitor 实现 `VisitBool`。

所以它适合：

```text
节点类型稳定
操作种类持续增加
```

不适合 AST 节点本身还在频繁扩展的早期系统。

## 测试

Visitor 测试应该用一个包含多个节点类型的小对象图，确认：

- 每种节点被访问；
- 遍历顺序符合约定；
- visitor 错误能停止遍历。

## 真实 Go 世界

读 `go/ast`、编译器、静态分析工具时会频繁遇到 Visitor/Walker 思路。对于普通 CRUD 业务对象则很少需要它，别为了“23 种模式必须用”而硬套。

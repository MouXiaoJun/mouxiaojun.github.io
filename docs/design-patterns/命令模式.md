# 命令模式 Command

> **核心思想：**把“要执行的动作”封装成一个对象，使动作可以排队、记录、重试、延迟执行或跨进程传输。

命令模式在后端里非常实用：任务队列、CQRS Command、定时任务、审计、重试系统本质上都在把“调用”变成数据。

## 从直接方法调用开始

```go
invoiceService.Generate(ctx, orderID)
```

如果现在要求：

- 放进队列异步执行；
- 失败重试；
- 保存 command id 做幂等；
- 记录耗时和审计；

直接方法调用就不够表达这些元数据。

## Command 接口

```go
type Command interface {
    Name() string
    Execute(ctx context.Context) error
}
```

具体命令：

```go
type GenerateInvoice struct {
    OrderID string
    Service InvoiceService
}

func (c GenerateInvoice) Name() string { return "invoice.generate" }

func (c GenerateInvoice) Execute(ctx context.Context) error {
    if c.OrderID == "" {
        return errors.New("order id is required")
    }
    return c.Service.Generate(ctx, c.OrderID)
}
```

统一执行器：

```go
type Bus struct {
    logger *slog.Logger
}

func (b *Bus) Execute(ctx context.Context, cmd Command) error {
    start := time.Now()
    err := cmd.Execute(ctx)

    b.logger.InfoContext(ctx, "command executed",
        "command", cmd.Name(),
        "duration", time.Since(start),
        "error", err,
    )
    return err
}
```

所有命令自动获得一致的 tracing/logging/retry 包装点。

## 跨进程时不要直接序列化带依赖的 struct

上面的 `GenerateInvoice` 持有 `InvoiceService`，适合进程内 Command。要进消息队列，应把数据和执行器分开：

```go
type GenerateInvoicePayload struct {
    OrderID string `json:"order_id"`
}

type GenerateInvoiceHandler struct {
    service InvoiceService
}

func (h *GenerateInvoiceHandler) Handle(ctx context.Context, p GenerateInvoicePayload) error {
    return h.service.Generate(ctx, p.OrderID)
}
```

消息只保存：

```json
{
  "type": "invoice.generate",
  "version": 1,
  "payload": {"order_id": "order-42"}
}
```

依赖由 worker 的 composition root 注入。

## 幂等比 Command 本身更重要

任务队列通常是 at-least-once delivery。同一个命令可能执行两次：

```text
worker 执行成功
↓
ack 前网络断开
↓
消息重新投递
```

因此真实 Command 应考虑：

```go
type Envelope struct {
    ID        string
    Type      string
    CreatedAt time.Time
    Payload   json.RawMessage
}
```

Handler 根据 `ID` 做幂等，而不是假设“命令只执行一次”。

## 测试

```go
func TestGenerateInvoiceValidatesOrderID(t *testing.T) {
    cmd := GenerateInvoice{}
    if err := cmd.Execute(context.Background()); err == nil {
        t.Fatal("expected validation error")
    }
}
```

## 什么时候适合

- 行为要异步化、排队、重试；
- 需要统一审计和 metrics；
- 调用需要保存成可重放记录；
- CQRS 写模型。

简单同步调用不需要为了模式再包装一个 `Command` struct。

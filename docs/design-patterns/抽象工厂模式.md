# 抽象工厂模式 Abstract Factory

> **核心思想：**创建一整组彼此匹配的对象，而不是只创建一个对象。

普通工厂回答的是“我要哪个实现”；抽象工厂回答的是“我要哪一套实现族”。在后端工程里，多云、多支付厂商、多消息系统适配都很容易出现这种需求。

## 场景：一套云厂商能力必须成组切换

假设应用依赖：

- 对象存储；
- 消息队列；
- Secret Store。

AWS、阿里云都有对应实现。如果业务代码分别判断：

```go
if provider == "aws" { ... }
if provider == "aliyun" { ... }
```

很容易出现错误组合：对象存储用了 AWS，队列却意外用了阿里云测试配置。

抽象工厂让“一套 provider”成为一个整体。

## 定义产品接口

```go
package cloud

import "context"

type ObjectStore interface {
    Put(ctx context.Context, key string, data []byte) error
    Get(ctx context.Context, key string) ([]byte, error)
}

type Queue interface {
    Publish(ctx context.Context, topic string, body []byte) error
}

type SecretStore interface {
    GetSecret(ctx context.Context, name string) (string, error)
}
```

## 定义抽象工厂

```go
type Factory interface {
    ObjectStore() ObjectStore
    Queue() Queue
    SecretStore() SecretStore
}
```

AWS 工厂：

```go
type AWSFactory struct {
    s3      *S3Client
    sqs     *SQSClient
    secrets *SecretsManagerClient
}

func NewAWSFactory(cfg AWSConfig) (*AWSFactory, error) {
    // 在这里统一初始化 region、credential、endpoint 等共享配置。
    return &AWSFactory{
        s3:      NewS3Client(cfg),
        sqs:     NewSQSClient(cfg),
        secrets: NewSecretsManagerClient(cfg),
    }, nil
}

func (f *AWSFactory) ObjectStore() ObjectStore { return &AWSObjectStore{f.s3} }
func (f *AWSFactory) Queue() Queue             { return &AWSQueue{f.sqs} }
func (f *AWSFactory) SecretStore() SecretStore { return &AWSSecretStore{f.secrets} }
```

阿里云工厂同样实现 `Factory`：

```go
type AliyunFactory struct {
    oss *OSSClient
    mq  *RocketMQClient
    kms *KMSClient
}

func (f *AliyunFactory) ObjectStore() ObjectStore { return &AliyunObjectStore{f.oss} }
func (f *AliyunFactory) Queue() Queue             { return &AliyunQueue{f.mq} }
func (f *AliyunFactory) SecretStore() SecretStore { return &AliyunSecretStore{f.kms} }
```

## composition root 只选择一次

```go
func NewCloudFactory(cfg Config) (cloud.Factory, error) {
    switch cfg.CloudProvider {
    case "aws":
        return cloud.NewAWSFactory(cfg.AWS)
    case "aliyun":
        return cloud.NewAliyunFactory(cfg.Aliyun)
    default:
        return nil, fmt.Errorf("unsupported cloud provider %q", cfg.CloudProvider)
    }
}
```

业务 Service 完全不知道厂商：

```go
type BackupService struct {
    store cloud.ObjectStore
    queue cloud.Queue
}

func NewBackupService(factory cloud.Factory) *BackupService {
    return &BackupService{
        store: factory.ObjectStore(),
        queue: factory.Queue(),
    }
}
```

这保证了同一个 Service 拿到的是同一产品族。

## 为什么不是一个巨大的 CloudClient

你也可以写：

```go
type CloudClient interface {
    PutObject(...)
    PublishMessage(...)
    GetSecret(...)
}
```

但最终很容易形成一个几十上百方法的胖接口。

抽象工厂的价值在于：**创建时成组，使用时仍然按能力拆成小接口。**

## 测试可以提供 InMemoryFactory

```go
type MemoryFactory struct {
    Store *MemoryObjectStore
    Q     *MemoryQueue
}

func NewMemoryFactory() *MemoryFactory {
    return &MemoryFactory{
        Store: NewMemoryObjectStore(),
        Q:     NewMemoryQueue(),
    }
}

func (f *MemoryFactory) ObjectStore() ObjectStore { return f.Store }
func (f *MemoryFactory) Queue() Queue             { return f.Q }
func (f *MemoryFactory) SecretStore() SecretStore { return NewMemorySecretStore() }
```

集成测试不需要真正访问云厂商。

## 什么时候适合

- 多云能力需要整体切换；
- 支付平台同时提供支付、退款、查单、对账等一组 client；
- 数据库方言需要成组创建 Repository / QueryBuilder；
- 不同部署环境要求一整套实现保持一致。

## 什么时候不适合

如果只有一个产品：

```text
provider -> Sender
```

普通 Factory 就够了。

如果产品之间根本没有“族”的概念，也不要为了模式而强行放到同一个 Factory。

## 和工厂模式的关系

```text
Factory Method
    输入 -> 一个产品

Abstract Factory
    输入 -> 一组彼此兼容的产品
```

Go 项目里抽象工厂通常不会长得像 Java 教科书中的很多抽象类；它往往就是一个**返回多个小接口的接口或 struct**。
